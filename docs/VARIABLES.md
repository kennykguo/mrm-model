Kinds of runtime values:

- `state`: carried from one step to the next.
- `tick`: computed again in every step (or at every controller edge).
- `cache`: exact speed cache (a key and its value); no effect on results.
- `counter`: counter or diagnostic for the run report.
- `ctrl_io`: controller input or output (sensor release, command registers).
- `truth`: Truth or metric input; never reaches a controller.
- `frozen`: written once when the plant is built; the kernel only reads it.
- `unused`: in the layout, but no code reads or writes it.

## 4. Per-tick state

One plant step [k, k + h) runs these parts in this order (kernel._world_loop). Each table lists the values the part writes.

| # | key | part | what it does |
|---|---|---|---|
| 0 | `build` | Plant build | Plant._build packs PlantParams into KParams and allocates KState (once per run). |
| 1 | `reset` | Reset | Plant._reset (and Plant.settle) write the initial values of a run. |
| 2 | `edge` | Controller edge | At a controller edge: fast kernel, sensor release, observation packing, controller step, clip and push of the command, next edge. |
| 3 | `latch` | Commands latched | Commands whose latch tick is k leave the controller pipeline and reach the DAC command inputs and the other registers. |
| 4 | `scenario` | Scenario | The scenario signals at k and k + h; the controller-reset fault. |
| 5 | `laser` | Laser lines | Line frequencies and powers, the turn-on ramp and the chip input loss. |
| 6 | `data` | Data path | Ones density, driver enable, transition density, swing and bias offset; the bit pattern of the tick. |
| 7 | `fault` | Fault mask | The fault flags of the scenario and the dac_glitch code offset. |
| 8 | `bias` | Bias DAC | Latch, fast-kernel offset, latency FIFO, code transfer, noise, slew and settle. |
| 9 | `nrz` | NRZ levels | The junction reverse voltage of the two NRZ levels. |
| 10 | `optics_in` | Optics inputs | Ring optics at the previous ring temperature (phases, loss, coupling), the thermo-optic slope, the junction capacitance and the bounds of the self-heating solve. |
| 11 | `activity` | Data-activity heat | Junction and driver heat of the data traffic. |
| 12 | `thermal_in` | Thermal inputs | The source powers of the thermal system at the start and end of the step. |
| 13 | `substep` | Substep length | The step length h (1 tick, or a power of two at the auto policy) and the values of the previous step that the auto rules compare. |
| 14 | `heater_split` | Heater TCR split | The heater-resistor temperature without this step's own heater power, and the self gain. |
| 15 | `heater` | Heater DAC path | Latch, fast-kernel offset, latency FIFO, glitch, code transfer, slew and settle, driver law with the heater TCR, supply limit. |
| 16 | `thermal` | Thermal and self-heating step | The implicit thermal step with the self-heating solve of every ring in bus order; the optics walk runs inside it. |
| 17 | `sense_in` | Sensor inputs | PD power, bus power, PD and ADC temperature, dark current, declared line, OMA and BER of the interval. |
| 18 | `sensors` | Sensors | Monitor ADC, error counter, temperature sensors and heater readback of each tick of the step. |
| 19 | `truth` | Truth | Ground truth of the state at k + h (never seen by a controller). |
| 20 | `oracle` | Oracle | The best achievable relOMA (on its period). |
| 21 | `metrics` | Metrics and records | Streaming metric accumulators and decimated records. |
| 22 | `bookkeeping` | Step bookkeeping | Detuning rate of the step, step and tick counters. |
| 23 | `never` | No writer | No code writes this value. |
