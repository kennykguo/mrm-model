# Tool choices and tradeoffs

Primary maintainer/vendor sources checked 2026-10-09. This is a broad survey of the relevant solver classes, not a claim to enumerate every product or establish an accuracy leaderboard. Accuracy depends on equations, geometry, material data, boundary conditions, mesh convergence, calibration, and the requested observable. Academic access and commercial prices have not been verified.

The capstone needs three different jobs: offline extraction of optical/electrical/thermal behavior; fast time-domain simulation of the resulting plant and measurements; and eventual verification of a digital controller. Coding the compact model makes controller experiments inspectable. Coding a replacement for a mature Maxwell or semiconductor solver would add substantial verification work.

## What this project uses

Python/NumPy and SciPy implement the independently derived compact equations, stiff integration, exact linear thermal propagation, fitting, and reproducible experiments. Matplotlib produces diagnostic plots. The spatial thermal example assembles a conservative finite-volume layered slab using SciPy sparse operators; its geometry and materials are explicit assumptions, not the Lightmatter package. scikit-fem is a considered alternative, not the solver behind that result. The dependency lock records software versions. The repository's run artifacts and tests, rather than this survey, establish which extraction backends were actually executed.

No result is described as a Meep, DEVSIM, Tidy3D, Lumerical, or COMSOL validation unless an actual run and its inputs, outputs, and convergence evidence exist. Prior use in `photonics-simulations` is educational context only.

## Open tools

| Tool | Best role | Main tradeoff for this MRM task | Primary documentation |
|---|---|---|---|
| Meep | Full-wave FDTD of couplers, bends, scattering, resonances; independent electromagnetic checks. | Three-dimensional ring simulation is expensive; a two-dimensional effective-index approximation does not establish 3D device accuracy. No built-in target semiconductor/thermal/control calibration. | [Meep methods](https://meep.readthedocs.io/en/latest/Introduction/) |
| MPB | Electromagnetic eigenmodes and dispersion in suitable dielectric structures. | Excellent complement to FDTD; not a heat, carrier-transport, or controller simulator. Treat supercell size and modal convergence explicitly. | [MPB introduction](https://mpb.readthedocs.io/en/latest/Introduction/) |
| Femwell | Waveguide/bent-mode FEM, overlaps, coupling, and static/transient heat problems. | Convenient Python bridge between geometry and extraction; examples may be ahead of documentation, and target-process validation remains the user's responsibility. | [Femwell](https://helgegehring.github.io/femwell/) |
| scikit-fem | Assemble custom finite-element mass/conductance operators for transparent thermal examples. | A numerical library, not a validated photonics multiphysics product. Boundary conditions, source normalization, and reduction must be implemented and checked. | [scikit-fem](https://scikit-fem.readthedocs.io/en/latest/index.html) |
| Elmer FEM | Package/substrate heat flow, Joule heating, and general multiphysics. | More setup and geometry/meshing work; still requires an optical compact model and device calibration. | [CSC Elmer](https://research.csc.fi/eosc-services/elmer-3/) |
| DEVSIM | Poisson/carrier-transport extraction, C-V, I-V, small-signal and transient semiconductor behavior. | Open finite-volume TCAD with user equations; doping/contact/material data are essential. Requires modal overlap to turn carrier profiles into optical shifts/loss. | [DEVSIM](https://devsim.org/introduction.html) |
| GDSFactory/gplugins | Reusable layout, layer stacks, meshing, and adapters to optical/thermal/TCAD tools. | Workflow infrastructure does not establish physical accuracy. Plugin backends have separate installation, capability, and licensing requirements. | [gplugins](https://gdsfactory.github.io/gplugins/) |
| SAX | JAX frequency-domain S-parameter circuits, gradients, and multi-ring/network spectra. | Supplies circuit composition; thermal state, high-speed cavity memory, sensors, and event timing need separate models. | [SAX](https://github.com/gdsfactory/sax) |
| Simphony | Python circuit construction and component libraries built around S-parameter models. | Convenient circuit-level abstraction; component validity and temporal electrothermal behavior still require explicit modeling. | [Simphony introduction](https://simphonyphotonics.readthedocs.io/en/stable/tutorials/intro.html) |
| Photontorch | Differentiable time/frequency photonic network models using PyTorch. | Useful for optimization; assess numerical method, supported components, and current dependencies against the intended dynamics. It does not supply target parameters. | [Photontorch](https://github.com/flaport/photontorch) |
| ngspice / Xyce | Heater/driver/TIA circuits, parasitics, electrical noise, behavioral co-simulation. | Optical fields and thermal maps require appropriate behavioral models; analog simulator support for those models differs. | [ngspice](https://ngspice.sourceforge.io/), [Xyce](https://xyce.sandia.gov/) |
| FDTDX / fdtd-z | GPU-oriented full-wave experiments and differentiable design. | Promising specialized alternatives; inspect GPU support, dispersion/loss/boundaries and output extraction before adoption. Their existence is not a demonstrated speed or accuracy result for this project. | [FDTDX](https://github.com/ymahlau/fdtdx), [fdtd-z](https://github.com/spinsphotonics/fdtdz/blob/main/README.md) |
| Verilator + cocotb | Test a later SystemVerilog controller with the plant's sampled I/O contract. | Validates digital logic, arithmetic and scheduling, not physical fidelity. An executable software interface alone is not an FPGA implementation. | [Verilator](https://verilator.org/guide/latest/overview.html), [cocotb](https://www.cocotb.org/) |

## Practical selection

Start with the auditable compact model and its measurement interface, then calibrate the parts that dominate controller decisions: thermal response and headroom, resonance/port slopes, monitor noise, and event timing. For an open extraction workflow, Meep or a vector mode/FEM solver can establish optical components, DEVSIM can establish a junction when its doping is known, and Femwell/Elmer can establish heat maps. SAX becomes useful when circuit routing and multiport connectivity outgrow a small explicit bus model.

If university access is available, the documented Lumerical workflow is a strong first commercial comparison; COMSOL is useful when package geometry and mixed boundary physics dominate. Neither should be run at each feedback tick. Export measured/extracted tables or passive thermal operators with units, reference planes, mesh/timestep evidence, interpolation limits, and provenance.

The meaningful benchmark is agreement on the same observable under the same inputs: resonance spectrum, heater-to-resonance step, monitor impulse response, or modulated eye. Agreement between two codes using the same wrong material or geometry does not establish device accuracy. A solver call without mesh/domain convergence is an extraction attempt, not a high-fidelity validation.
